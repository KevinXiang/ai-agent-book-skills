# 第 7 章 模型后训练

## Core Idea / 核心观点

模型后训练的本质是把交互策略写进参数。Agent = LLM + 上下文 + 工具,本章聚焦"优化 LLM 这个大脑"——通过后训练让模型更好地利用上下文和工具。它建立在前一章(评估体系与仿真环境)这两块基石之上,讨论如何真正改动模型权重,把能力沉淀进参数。

本章贯穿两条主线:
- **主线一:SFT 记忆,RL 泛化**。在 GeneralPoints 和 V-IRL 等对照实验(相同任务、相同模型、相同预算,唯一变量是训练方法)中,SFT 对训练答案过拟合,RL 在分布变化(OOD)的测试中更容易学到可迁移策略。**这是实验结果而非普遍属性**——数据足够多样、正则化得当时 SFT 也能泛化,奖励或环境有偏时 RL 也会过拟合。
- **主线二:数据和环境,比算法更重要**。现成的 RL 算法(PPO、GRPO 等)你会用就行,真正决定成败的是仿真环境的保真度和训练数据的质量。很多场景下,只要 SFT 的数据质量到位,你根本不需要做 RL。

## Frameworks Introduced / 引入的框架

### 1. 三阶段全景:模型能力怎么炼成

| 阶段 | 数据 | 优化目标 | 学到什么 | 代价 |
|---|---|---|---|---|
| 预训练 | 海量互联网文本 | 预测下一个词 | 语言规律、世界知识、基本推理 | 极高(数百万~数千万美元) |
| SFT | 几千~几万条"输入-输出"示范对 | 预测下一个词(只在回答上算损失) | 指令遵循、输出格式、风格、流程协议 | 低(几小时~几天) |
| RL | 任务、环境 + 奖励信号 | 最大化期望奖励 | 可迁移的决策策略、探索出的新解法 | 高(常是 SFT 的几十~上百倍) |

直觉类比:预训练 = 读万卷书;SFT = 老师手把手教标准解法;RL = 自己下场做题、根据对错反复打磨。

关键认知:SFT 在数学上和预训练是**同一个任务**(都是预测下一个词、最小化同一个损失函数)。差别只有两点:(1) 数据不同(结构化的"提问→理想回答"对);(2) 损失只算在回答上(loss masking,损失屏蔽)。一句话概括 SFT 本质:用极高的样本效率,把一套稳定的"输入→输出"映射与协议固化进参数。它固化的是"格式、风格、流程"这类协议性知识,而非大量事实性知识。

### 2. 两条主线背后的机制解释

- **为何"SFT 记忆,RL 泛化"可能出现**:SFT 最大化标注回答的概率(极大似然),推动模型复现示范;RL 最大化期望奖励,模型探索多条路径并提高高奖励路径概率。还有更深机制——mode-seeking(寻峰):反向 KL 约束的策略优化可能把概率集中到少数高奖励模式,而极大似然 SFT 可能表现出 mass-covering(覆盖式)倾向。
- **优先级反转**:OpenAI 训练范式演进揭示,几十年 RL 研究者把优先级搞反了——不是"算法 > 环境 > 先验",而是"先验(基础模型) > 环境 > 算法"。

### 3. 奖励信号设计谱系(密度 + 表示形式)

密度维度:稀疏(二元奖励:成功=1/失败=0)→ 里程碑奖励 → 过程奖励(每步骤即时反馈)→ 密集连续。
表示形式:标量 → 半标量(先分析优缺点再给分)→ 向量(多维度分项打分)→ 生成式(自然语言讲理由+多次采样)。

核心演化:**奖励结果,约束过程**(RLVP 的配方)。总奖励 `R = O + β·Φ`,O 是结果奖励(稀疏、真正的目标),Φ 是路径信号(确定性规则引擎逐动作给出)。Φ 两种用法:惩罚(−λ,扣违规动作分)、守规奖励/部分奖励(+μ,奖励合规/进展动作)。

为何有效的统一解释——**组内方差(within-group variance)**:GRPO 的优势本质就是组内方差。纯结果奖励在全败组(训练早期)和全胜组(训练后期)都"瞎的"(方差为零、无梯度)。可验证的惩罚永远能补回方差(坏动作可查),进展奖励只在部分成功可达时满足。

### 4. SFT vs RL 决策框架

实际决策顺序:
1. **先问:需要后训练吗?** 如果通过 Harness 工程(优化 prompt、工具设计、上下文管理)就能解决,不需要训练模型。大多数 Agent 应用落在这里。
2. **如果需要训练:先试 SFT。** 适用于固化输出格式、固化协议性知识、统一风格。不适合注入大量事实性知识(那需要继续预训练或 RAG)。SFT 成本低、见效快。
3. **SFT 不够时:加 RL。** 适用于需要泛化到新场景、需要探索最优策略、或标注成本过高。如果输出尚不稳定,先 SFT 或约束解码稳定格式再 RL;强基础模型可直接 RL。

转 RL 的临界点:**当"无论增加多少多样、优质的示范,新场景表现仍然停滞",且有能可靠评估的奖励与环境时**。

"先形后神"(借中国画说法):SFT 先把"形"(格式、结构)立起来,RL 再追求"神"(策略、泛化)。SFT 应训练到"格式稳定、能力初具"即可,不宜恋战。

## Key Concepts / 关键概念

- **LoRA**(Low-Rank Adaptation,低秩适配):不动原始大权重矩阵,只在旁边挂一个很小的"补丁"(低秩矩阵)。参数量仅占 1%-5%,接近全参微调效果。实践要点:必须应用到所有主要权重矩阵(尤其 MLP 层);最优学习率约是全参微调的 10 倍;SFT 用中高 rank(64-256),RL 用小 rank(8-32)甚至 rank=1。
- **拒绝采样微调(RFT)**:对每条提示采样 k 条候选(常取 4-16)→ 用规则验证器判对错 → 只保留正确轨迹、去重、限制每提示条数 → 做 SFT。介于纯 SFT 与 RL 之间,是可验证任务上性价比极高的数据构造手段。
- **RLHF**(基于人类反馈的强化学习)三段式管线:SFT → 训练奖励模型(基于 Bradley-Terry 模型,采集两两比较而非绝对分数)→ 用 RM 打分做 PPO。KL 惩罚 `r = r_RM − β·KL(π_θ‖π_ref)`,防止策略离参考模型太远(否则 RM 分数不可信)。
- **RLVR**(可验证奖励的强化学习):奖励来自规则验证器(测试通过、答案正确),不是学出来的 RM。Agent 任务大多可验证,故本章以 RLVR 为主线。RLHF 负责对话质量与安全对齐,RLVR 负责推理与 Agent 能力,实际部署叠加使用。
- **DPO**(直接偏好优化):跳过显式 RM,把偏好对直接变成带隐式奖励的分类损失。像 SFT 一样简单,无需在线采样/价值网络。代价是完全离线,无法探索偏好数据之外的新行为。
- **mode-seeking(寻峰)/ mass-covering(覆盖式)**:反向 KL 可能集中到少数高奖励模式;极大似然 SFT 可能覆盖多个模式。具体行为取决于数据、奖励、KL 方向与系数。
- **信用分配(Credit Assignment)**:多步序列中判断哪一步对最终结果贡献最大。PPO 用 GAE(广义优势估计)逐步估计;GRPO 把整条 response 视为单一动作,优势均摊到所有 token(长程任务会稀释信号);turn-level 分摊是折中。
- **Goodhart 定律**:一个指标一旦成为优化目标,它就不再是好指标。RM 会被"过度优化"(reward model over-optimization),代理奖励单调上升而真实质量先升后降。

## Mental Models / 心智模型

1. **地图与指南针**:SFT 细致学习已有地图(模仿示范),RL 则拿着奖励这枚指南针探索地图外的候选路线。地图或指南针不准都会迷路。许多系统先用 SFT 建立稳定起点,再在奖励与环境足够可信时加入 RL。

2. **不对称验证器**(理解 RLVP 的钥匙):在可机器判定的环境里,"检测坏动作"便宜可靠(坏动作有明确确定特征),"判定有意义进展"昂贵易错(几乎和"解决任务"一样难)。因此环境能可靠提供的密集信号,本质是"路径上的惩罚",而不是"进展上的奖励"。

3. **"先验 > 环境 > 算法"的用力顺序**:合理顺序是 先选强基础模型 → 再把环境和数据打磨到位 → 最后才在算法和超参上做边际优化。环境和数据没做好就去卷算法,是典型南辕北辙。

4. **不对称性复用**:RLVR 依赖"验证比生成容易";On-Policy Self-Distillation(OPSD)依赖"对着答案讲题远比独立解题容易"——同一种不对称被用来产生稠密监督而非稀疏标量。

## Anti-patterns / 反模式

1. **过度依赖后训练记忆事实**。应该用 RAG 管理事实知识(可动态更新、可追溯、不遗忘),后训练聚焦于"如何使用知识"。
2. **格式未稳定就引入 RL**。模型不能稳定生成奖励计算所需的 JSON 时,训练信号变噪声。先用小规模评估设格式稳定性门槛,必要时 SFT 或约束解码稳定后再 RL。
3. **奖励函数设计不当导致 reward hacking**。模型学会钻漏洞刷高分(如只看回复长度就生成冗长空话)。应评估最终目标而非中间指标。
4. **忽视仿真保真度**。仿真过于简化或环境响应不真实,训练出的策略上线就露馅——"练习场跟考场不是一回事"。这是 RL 项目最常见的翻车方式。
5. **过度训练导致泛化下降**。训练损失持续下降但验证集性能恶化时,模型正在死记细节。SFT 尤其容易出现,早停至关重要。
6. **低估 RL 的计算成本**。SFT 表现良好的任务转 RL 可能需 10-100 倍训练时间。若测试分布与训练高度一致,SFT 可能已足够。
7. **不作为陷阱(inaction trap)**:只有惩罚、没有结果奖励时,最优策略是"什么都不做"(零违规但零成功)。结果奖励始终是主驱动力,惩罚只负责"怎么做"。
8. **只惩罚"没进展"而非"坏动作"**。"不做任何动作"正是规避"没进展惩罚"最省事的办法——会把 Agent 直接教成什么都不干。

## Code Examples / 代码示例

**SFT 数据格式示例**(loss masking 只对回答部分回传梯度):

```jsonl
{"messages": [
  {"role": "user", "content": "用 [7, J, 3, 5] 计算 24"},
  {"role": "assistant", "content": "<think>J=10,(10-7)×(5+3)=3×8=24</think>\\boxed{(J-7)×(5+3)}"}
]}
```

**RLVP 奖励函数骨架**(奖励结果,约束过程):

```python
def reward(trajectory, outcome_reward):
    """R = O + β·Φ,两路分别归一化后合并"""
    O = normalize(outcome_reward)          # 稀疏结果奖励(任务是否完成)
    penalty = 0.0   # -λ:每出现一次可机器判定的违规动作(rm -rf、改测试文件)扣分
    partial   = 0.0   # +μ:每出现一次可验证的好动作(满足前置条件、测试数变多)加分
    for action, state_before in trajectory:
        if is_verifiable_violation(action, state_before):
            penalty -= lam
        if is_verifiable_progress(action, state_before):
            partial += mu
    Phi = normalize(penalty + partial)
    return O + beta * Phi
```

| 维度 | SFT | RL |

| 训练稳定性 | 高、收敛快 | 低、易震荡,需小心调 |

| 类型 | 密度 | 示例 | 适用场景 |

## Worked Example / 实战案例

### SFT 记忆 vs RL 泛化(GeneralPoints 实验 7-11)

任务类似"24 点":用四张牌通过加减乘除凑出 24。设计两个分布偏移:
- **规则变体**:训练时 J/Q/K 都计为 10,测试时分别计为 11/12/13。
- **视觉变体**:训练用黑色花色(♠♣),测试用红色花色(♥♦)。

基于 Llama-3.2-Vision-11B,先 SFT 初始化,再在相同预算下分别扩展 SFT 与 RL(带价值网络的 PPO)。

**OOD 测试结果(相对 SFT Init 基线变化)**:
- 规则 OOD(GP-L):SFT −8.1%(11.5→3.4),RL +3.5%(11.5→15.0)
- 视觉 OOD(GP-VL):SFT −9.9%(23.6→13.7),RL +17.6%(23.6→41.2)

**机制解释**:有限的 SFT 数据强化了"遇到 J/Q/K 就当 10 用"的固定模式;测试时 J=11,模型仍按 10 计算。结果导向的 RL 更可能强化"重新计算直到得到正确答案"的策略,因而 J 变成 11 时仍能应用。RL 还反向改善了底层视觉编码器(结果导向信号传到感知层);SFT 因过度拟合思考过程的 token 模式,忽视视觉 token 学习。

**关键前提**:未经 SFT 的端到端 RL 完全失败(输出无结构,奖励无法计算)——印证"先形后神"。但这有边界:足够强的基础模型(如 DeepSeek-R1-Zero)可跳过 SFT 直接 RL 成功,代价是输出可读性差,故 R1 最终加回"冷启动 SFT"。

### 奖励设计演化:从二元到"奖励结果、约束过程"

Pine AI 打电话办 Xfinity 套餐:二元奖励需 100 次试错才偶然成功。根因——model-free RL 只看最终 reward=0,无法从客服明确说的"需要信用卡后四位"中学习。演化路径:标量(7.2 分,无诊断)→ 半标量(优缺点+6.5 分)→ 向量(分维度定位短板)→ 生成式(自然语言多次采样分析)。最终 RLVP 把环境能可靠提供的"路径惩罚"和可达时的"进展奖励"补回组内方差,让全败组采样不白跑。

## Key Takeaways / 关键要点

1. **SFT 和 RL 不是竞争,而是经常按顺序组合**。结构化输出不稳定时先 SFT 立"形",再 RL 求"神"。"SFT 记忆、RL 泛化"是受控实验中观察到的倾向,不是普遍规律。
2. **数据和环境,比算法更重要**。现成 RL 算法你会用就行。真正拉开差距的是仿真环境保真度和训练数据质量。造不出真实环境时,用模型模拟环境(ZeroSearch 模拟搜索引擎、DreamGym 蒸馏环境动态)可行,但模拟器偏差就是训练天花板。
3. **很多场景下,只要 SFT 数据质量到位,根本不需要做 RL**。RL 又贵又不稳定(几十~上百倍成本)。先把 SFT 数据做好,再判断要不要 RL,这个顺序能省大量算力。
4. **RL 的主要瓶颈是样本效率**。两个最有希望的方向:On-Policy Distillation(在轨+稠密信号,步数约纯 RL 的 1/10)和 RLVP("奖励结果、约束过程",用可达进展的部分奖励救回全败组采样)。共同点是把环境里本就存在却被纯结果奖励浪费的信息,重新变成可学习的信号。
5. **没有更强教师时**,On-Policy Self-Distillation(OPSD)让同一模型以"看答案的教师"和"只见题的学生"两种身份互监督,把稠密信号带到奖励不可验证的任务上。
6. **工具调用 RL 的工程细节**:对环境反馈 token 做 loss masking(只对模型自生成 token 回传梯度),ReTool、Search-R1、veRL 等主流框架都内置了这一机制。
7. **评估环境可复用 ≠ 评估数据可直接训练**。SWE-Bench Verified 等评估子集必须与训练数据严格隔离。

## Connects To / 关联章节

- **第 6 章**(评估体系与仿真环境):本章的两块基石。"评估环境提供的奖励信号质量直接决定 RL 训练效率",但训练数据与评估数据必须分开。
- **第 1、4 章**(ReAct 循环):多轮交互的物理形态就是思考→行动→观察的迭代,奖励延迟来自"最终结果好坏要在多轮后才能判断"。
- **第 2 章**(注意力机制):上下文学习效果与内部机制是两回事(注意力更像检索而非推理),但不妨碍其任务适应效果。
- **第 8 章**:把模型参数放回完整 Agent 系统——参数只是知识、指令、程序、参数四种更新载体之一,其独特问题是从部署轨迹获取可信学习信号、选择正确更新位置、治理版本验证发布回滚。涉及具体训练算法时第 8 章直接引用本章。
- **第 9 章**(VLA):"视觉编码器 + 投影层 + LLM"骨架再延伸输出动作即是 VLA;SimpleVLA-RL 是把 RL 引入机器人 VLA 架构的代表(实验 7-13);动作分块完整讨论见第 9 章控制层。
