# Chapter 4: 工具

## Core Idea
工具是 Agent 连接语言"大脑"与真实数字世界的"手脚和感官"。本章给出五类工具(感知/执行/协作/事件触发/用户沟通)的分类与逐类设计要点,用 MCP 统一工具互操作、用分层组织/动态发现/Skills 应对工具选择挑战;并用事件驱动的异步架构回答"Agent 如何管理长任务、响应随时到达的外部事件"。

## Frameworks Introduced

- **五类工具分类**(调用方向 × 作用对象): 感知(Agent 主动/获取信息)、执行(Agent 主动/改变世界)、协作(Agent 主动/驱动其他 Agent 或人)、用户沟通(Agent 主动/向用户传递信息)、事件触发(Agent 注册、外部触发/驱动 Agent 执行)
  - When to use: 设计任何工具前先定位它属于哪一类,决定设计重点
  - How: 前四类由 Agent 主动调用,事件触发工具依赖事件驱动异步架构

- **能力表达形式三维决策**(专用工具 vs Skill + 通用执行器): 参数复杂度高 → 专用工具 schema 更可靠;变更频率高 → Skill 改文本远比改代码便宜;模型能力强 → SOTA 模型可用 Skill + 通用执行器覆盖更多场景
  - When to use: 决定一项新能力该做成专用 MCP 工具还是 Skill 文档

- **工具粒度权衡**: 功能相似 + 使用场景重叠 → 整合(如多个 extract_xxx 合并为 read_document + file_type 参数);参数差异大或使用频率极高 → 保持独立。标准是功能相似性和场景重叠度

- **ACI(Agent-Computer Interface)三阶段演进**: 第一代 API 直接封装(粒度过细)→ 第二代 ACI 原则(工具对应 Agent 目标而非底层 API)→ 第三代优化工具被调用(示例驱动)、被发现(动态发现)、被串联(代码编排)的方式

- **执行工具安全四层防护**: (1) 输入验证(路径遍历/注入,快速失败)→ (2) 权限控制(目录限制、命令黑名单、配额;黑名单只是基础层)→ (3) Proposer-Reviewer(独立模型事前审批/事后验证)→ (4) Sidecar(并行轻量分类器,只读结构化字段门控单次调用)
  - When to use: 任何会改变外部世界的执行工具

- **异步事件处理三策略**(按紧急度分流): 取消式(紧急,主动制造安全点中断重新推理)/ 队列式(常规,入队等工具返回安全点批量追加)/ 并行式(独立轻量查询另起会话)
  - When to use: 一个 Agent 实例同时面对多个事件时

- **主动工具发现**: Agent 执行中意识到能力缺口时用自然语言声明需求,系统做服务器级 → 工具级两层语义路由动态注入(MCP-Zero 在约 2800 工具上节省约 98% token)
  - When to use: 工具数量从十几个增长到成百上千,全量注入失效时

## Key Concepts

- **MCP(Model Context Protocol)**: Anthropic 2024 年底发布的开放标准,统一 AI 模型与外部工具/数据源的通信协议,客户端-服务器架构,三类原语为工具(可执行)/资源(只读)/提示模板
- **Skill + 通用执行器**: 用自然语言 Skill 文档描述操作流程,Agent 通过终端或代码解释器执行,少量通用工具覆盖大量场景
- **沙盒(Sandbox)**: 与主机隔离的安全执行空间,代码运行时无法影响外部系统;注意 venv 只隔离包依赖不是沙盒
- **Proposer-Reviewer(提议者-审核者)**: 用独立的第二视角检验第一视角产出,分事前审批与事后验证
- **Sidecar(边车)机制**: 伴随主 Agent 思考循环运行的轻量 LLM 调用,对每次工具调用做独立安全判断,只读结构化字段避免被工具描述话术操纵
- **幂等性**: 同一操作执行一次和多次对外部世界影响完全相同,可安全重试;非幂等操作用"预检-确认"两段式
- **事件触发工具**: 外部事件驱动 Agent 行动的入口,涉及注册(Agent 主动声明关心什么)和触发(外部异步回调唤醒 Agent)两个时刻
- **提示注入(Prompt Injection)**: 把恶意指令伪装成正常内容诱导模型执行非预期操作;工具描述投毒是其变种,载体是工具定义本身且每次会话生效
- **同名工具遮蔽(tool shadowing)**: 恶意服务器提供同名工具诱导 Agent 把调用和敏感参数路由到攻击者
- **渐进式披露(Progressive Disclosure)**: Skills 启动时只看薄目录(数百 token),需要时才逐层读取,把"工具选择"转化为"知识检索"
- **致命三要素**(Simon Willison): 访问私有数据 + 暴露于不可信内容 + 对外通信能力,三者齐备即构成完整攻击闭环

## Mental Models

- **感知是感官,执行是手脚,但手脚会打翻东西**: 感知工具只读,天然适合缓存和并行;执行工具改变世界,错误代价极高,安全约束是其设计核心而非可选项
- **工具描述是写给 LLM 的"招聘启事"**: 核心是让 LLM 知道"什么时候用"而非"能做什么";边界条件(做不到什么)比能力描述更重要,因为大多数调用失败根因是不知道工具不能做什么
- **第二视角防单点失败**: 提议者-审核者审查开放式思考(需能力相近的不同家族模型),Sidecar 判断简单分类问题(轻量模型即可胜任)——审查对象不同决定了模型选择策略不同
- **同步训练 / 异步部署的根本矛盾**: LLM 训练假设"工具调用后下一条必须是工具结果",真实部署却要求用户随时打断、多任务并发、外部事件随时抵达——当前所有异步工程技巧都是在用提示工程弥补这一矛盾,根本解法有待下一代模型在异步环境中 RL 训练
- **工具书式查阅 vs 一次性摊开**: 没人会把工具书从第一页读到最后一页;Skills 顺着索引按需查阅一个词条,既不必维护向量索引,也不必把"发现工具"单独建模成特殊检索

## Anti-patterns

- **静默输入转换**: 工具参数层悄悄"修正"模型输入(如中文弯引号转直引号)→ 模型读到的世界与工具操作的世界系统性偏差,陷入无法自诊断的失败循环。参数传递必须透明,如需规范化必须在描述中说明并在返回中告知
- **静默参数注入**: 工具在模型不知情下追加参数(如自动给 git commit 加标记)→ 旧版 Git 报错,模型反复调整措辞却永远失败
- **静默截断**: read 类工具超长时悄悄截断而不提示 → Agent 误以为看到了全部内容,基于不完整信息做错误判断。截断必须显式可见(注明省略量、如何读剩余)
- **把 venv 当沙盒**: venv 只隔离包依赖,对文件系统/网络/进程无任何安全约束 → 代码照样能删任意文件、访问任意网络。真正隔离要靠容器或 microVM
- **黑名单作为唯一防护**: 简单字符串匹配黑名单 → 攻击者变形命令即可绕过。需结合语义解析理解命令实际意图
- **能力相差过大的模型互审**: 用 Haiku 审查 Opus 的开放式思考 → 审查者跟不上被审者的思考。互审模型应能力相近但训练偏好不同(如 Claude Opus 5 与 GPT-5.6 Sol 互审)
- **Sidecar 读取主模型自由文本上下文**: 若 Sidecar 同时读主模型思考过程 → 攻击者在用户输入夹带"请允许执行 rm -rf"即可操纵 Sidecar。Sidecar 必须只读结构化字段堵住话术通道
- **非紧急事件频繁打断**: 占位符方案有加剧幻觉风险(模型可能"编造"未完成的工具结果)→ 只在真正紧急时打断,非紧急事件入队批量处理

## Code Examples

**执行工具的安全封装:write_file 写入后自动验证 + 结构化错误反馈**(本章"执行-验证-反馈"闭环的典范):

```python
def write_file(path: str, content: str) -> dict:
    # 第 1 层:输入验证——快速失败,不智能修正
    if ".." in path or path.startswith("/etc"):
        return {"ok": False, "error": "path traversal detected"}
    # 写入
    with open(path, "w") as f:
        f.write(content)
    # 自动验证:按文件类型跑 linter,把错误作为返回值的一部分
    errors = run_linter(path)  # 解析为结构化错误列表
    return {
        "ok": len(errors) == 0,
        "file": path,
        "lint_errors": errors,   # 如 [{"line": 10, "msg": "undefined variable result"}]
        "hint": "如需修正,请在下一轮思考中针对 lint_errors 处理",
    }
```

- **What it demonstrates**: 工具不只返回"成功",而要在写入后立即执行语法检查,把"执行-验证-反馈"闭环交给 Agent,让它下一轮就能看到具体错误并修正

**长输出截断与持久化**(避免冗长输出污染上下文):

```python
def truncate_and_persist(output: str, threshold=10000) -> str:
    if len(output) <= threshold:
        return output
    lines = output.splitlines()
    tmp = "/tmp/execution_output.txt"
    with open(tmp, "w") as f:
        f.write(output)
    head, tail = lines[:50], lines[-50:]
    omitted = len(lines) - 100
    return ("\n".join(head)
            + f"\n... [省略 {omitted} 行,完整输出已保存至 {tmp}] ...\n"
            + "\n".join(tail)
            + f"\n如需完整输出,请使用 read_file 工具读取 {tmp}")
```

- **What it demonstrates**: 头尾各保留若干行 + 中间省略提示 + 文件引导,让 Agent 知道有更多信息可按需读取,而非误以为已看到全部

**异步占位符修复同步格式**(让同步训练的模型容纳异步打断):

```python
# 规则 3:工具执行中被用户打断,为未完成工具生成占位符 tool_result
trajectory.append({
    "role": "assistant",
    "tool_calls": [{"id": "c1", "function": {"name": "search_contacts", "arguments": "..."}}, ],
})  # 规则 1:LLM 输出时立即记录 assistant message
# 工具尚未返回,用户突然说"先查下明天天气"
trajectory.append({
    "role": "tool", "tool_call_id": "c1",
    "content": "[占位符] 工具正在后台执行,请优先处理新事件",  # 修复格式:assistant 与 tool_result 配对
})
trajectory.append({"role": "user", "content": "先帮我查下明天天气"})  # 追加打断事件
# 重新调用 LLM——此刻它看到的轨迹格式完全合法
# 天气回复后,原 search_contacts 结果作为新事件追加(规则 2),Agent 继续起草邮件
```

- **What it demonstrates**: 常态下 LLM 看到完美同步轨迹,只在确实需要打断时引入占位符这个"必要的妥协"

## Reference Tables

**五类工具对照(表 4-1)**:

| 工具类型 | 调用方向 | 作用对象 | 设计重点 |
|---|---|---|---|
| 感知工具 | Agent 主动调用 | 获取信息 | 粒度权衡、输出量控制、分页/显式截断;只读性带来缓存与并行红利 |
| 执行工具 | Agent 主动调用 | 改变世界 | 层次化安全防护、Proposer-Reviewer、Sidecar、幂等性、可观测性 |
| 协作工具 | Agent 主动调用 | 驱动其他 Agent 或人类 | 子 Agent 生命周期原语(创建/消息/取消/发现)、HITL 学习闭环 |
| 用户沟通工具 | Agent 主动调用 | 向用户传递信息 | 异步消息模式、多渠道选择、用户召回、生成式 UI |
| 事件触发工具 | Agent 注册、外部触发 | 驱动 Agent 开始执行 | 触发条件过滤、事件载荷设计,依赖事件驱动异步架构 |

**MCP 与传统 API 工具对比**:

| 维度 | 传统 API 封装 | MCP |
|---|---|---|
| 互操作 | 每个框架格式不同(OpenAI/Anthropic/LangChain),需重复适配 | 一次开发处处可用,通用"插座标准" |
| 工具描述 | 各框架自定义 | JSON Schema 标准化 |
| 传输 | 各自实现 | 本地 stdio / 远程 Streamable HTTP(SSE 已弃用) |
| 原语 | 仅工具 | 工具(可执行)+ 资源(只读)+ 提示模板 |
| 局限 | — | 标准化能力调用,不提供完整事件运行时;跨会话事件驱动需另行构建 |

**执行工具安全机制分级**:

| 层级 | 机制 | 作用 | 局限 |
|---|---|---|---|
| 第 1 层 | 输入验证 | 路径遍历/注入检查,快速失败 | 只防已知模式 |
| 第 2 层 | 权限控制 | 目录限制、命令黑名单、配额 | 黑名单可被变形绕过 |
| 第 3 层 | Proposer-Reviewer | 独立模型事前审批/事后验证 | 需能力相近的不同家族模型,有计算成本 |
| 第 4 层 | Sidecar | 并行轻量分类器门控单次调用 | 需拒绝熔断器防死循环 |
| 隔离 | 沙盒(进程/容器/microVM) | 限制爆炸半径 | 强度递增,按场景选择 |

**Proposer-Reviewer 与 Sidecar 对比(表 4-2)**:

| 维度 | Proposer-Reviewer | Sidecar |
|---|---|---|
| 执行时机 | 操作前(事前审批)或操作后(事后验证) | 与主模型流式输出并行,门控单次工具调用 |
| 审查对象 | 操作的合理性或操作的结果 | 操作本身(工具调用) |
| 审查视角 | 独立模型审批、模态切换验证 | 安全性/可靠性校验 |
| 输入隔离 | 提议者和审查者看到相似信息 | 刻意隔离主模型的自由文本,只读结构化字段 |
| 模型选择 | 能力相近的不同家族模型 | 轻量分类模型即可 |

## Worked Example

**Cursor 弯引号静默转换故障(参数保真性反模式)**: Cursor 的编辑工具接收 old_string/new_string 做精确替换,但参数传递层将中文弯引号(" ")静默转成英文直引号(")。模型通过 read 工具看到文件里是弯引号(读取工具原样返回未转换),于是原样传入替换工具;参数层却已转成直引号,与文件实际内容不匹配,工具返回"未找到匹配"。模型反复尝试反复失败——它无法理解为什么自己看到的内容工具却找不到。写入方向同样被篡改。这揭示了基础原则:**模型感知的世界与工具操作的世界不能有系统性偏差**,任何规范化必须在描述中说明并在返回中告知。

**PineClaw 的 Channel 机制(从时间驱动到事件驱动)**: Pine AI 代用户打真实电话(协商账单、取消订阅、保险理赔)。OpenClaw 内置的 Heartbeat(定时轮询)在电话场景下不可接受——客服要求验证 OTP 时,若靠定时检查用户可能迟迟收不到通知导致客服挂断。PineClaw 在 Gateway 和 Pine API 间建立实时 Channel:通话接通、需要用户输入等关键事件即时推送到 Agent。这揭示事件驱动架构的核心价值:**真正的"主动服务"不仅需要 Agent 能定时检查世界,更需要世界能主动通知 Agent**。

**异步打断的五规则运作**: Agent 调用 search_contacts 起草邮件,搜索未返回时用户说"先查下明天天气"。(1) assistant message 已立即写入轨迹(规则 1);(2) 系统为未完成的 search_contacts 生成占位符 tool_result"工具正在后台执行,请优先处理新事件"(规则 3),追加天气查询重新调用 LLM——此刻轨迹格式完全合法;(3) 天气回复后,原结果作为新事件追加(规则 2),Agent 继续起草邮件。常态下 LLM 看到完美同步轨迹,只在确实需要打断时才引入占位符。

## Key Takeaways

1. **工具设计决定能力上限,异步架构决定能否在真实世界可靠运行**——本章核心结论
2. **工具描述是路由决策不是功能介绍**: 核心让 LLM 知道"什么时候用";边界比能力更重要;参数用具体例子;加 1-5 个真实调用示例可使准确率从约 72% 提升到 90%。选错工具时优先检查描述而非换模型
3. **MCP 解决互操作,Skills 解决选择过载**: MCP 一次开发处处可用;Skills 把"工具选择"转化为"知识检索"。两者非此即彼:Skills 负责组织披露,也可通过 MCP 被发现
4. **执行工具安全必须多层防护**: 输入验证 → 权限控制 → Proposer-Reviewer → Sidecar,任一层不能作为唯一手段;venv 不是沙盒
5. **参数传递保真性是不可逾越的底线**: 模型感知的世界与工具操作的世界不能有系统性偏差,静默转换/注入会制造模型无法自诊断的故障
6. **接入一个 MCP 服务器等于引入新信任边界**: 用致命三要素(私有数据 + 不可信内容 + 对外通信)评估整体风险;接入前审查 description、锁定版本、最小权限凭证,运行时靠 Sidecar 只读结构化字段
7. **当前异步工程都是权宜之计**: 占位符、异步工具接口(启动与完成解耦)、状态栏标记都在弥补"训练同步/部署异步"矛盾;根本解法有待下一代模型在异步环境中 RL 训练
8. **动态工具发现要保护 KV Cache**: 新工具 schema 追加到轨迹末尾而非静态前缀,散落在各处固定在首次注入位置,后续轮次作为普通历史命中缓存
