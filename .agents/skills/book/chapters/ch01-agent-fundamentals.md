# Chapter 1: AI Agent 入门

## Core Idea
现代 AI Agent 的本质是 **Agent = LLM + 上下文 + 工具**(大脑 + 眼睛 + 手脚),通过 ReAct 循环协同工作;在生产环境中则扩展为 **Agent = Model + Harness**,围绕模型补齐约束、验证、纠正三层保障。本章是全书的概念地图,为后续所有章节提供统一术语。

## Frameworks Introduced

- **Agent 核心公式(实现层)**: `Agent = LLM + 上下文 + 工具`
  - 直觉层: 大脑(LLM 决策) + 眼睛(上下文感知) + 手脚(工具行动)
  - 学术层: Policy + Observation Space + Action Space
  - When to use: 任何讨论 Agent 架构时的第一性原理
  - How: LLM 提供决策逻辑,上下文界定能看到的信息,工具界定能采取的行动

- **Agent 生产公式(Harness 层)**: `Agent = Model + [上下文 + 工具 + 约束 + 验证 + 纠正]`
  - 上下文/工具让 Agent "能做事";约束/验证/纠正让 Agent "不做错事"
  - When to use: 把 Demo 推向生产级产品时
  - How: 约束(故障安全默认值)、验证(输入隔离 + 结构化校验)、纠正(静默重试 + 熔断)

- **ReAct 循环**: Reasoning + Acting(实际包含思考→行动→观察三环节)
  - 上下文 = 静态前缀(系统提示词 + 工具定义) + 轨迹(动态消息历史)
  - When to use: 设计或分析任何 Agent 的执行循环

- **观察空间/动作空间扩展**: 在底层模型固定时,提升 Agent 表现的主要工程手段就是重新定义或扩展这两个空间
  - 把任务所需数据纳入上下文(扩观察空间),把所需操作封装成工具(扩动作空间)
  - 案例: Manus 合并 Deep Research + Coding + Computer Use;OpenClaw 把接口延伸到用户消息渠道和云应用

- **工具五分类**(感知/执行/协作/事件触发/用户沟通): 详见第 4 章,此处建立整体印象

## Key Concepts

- **Policy(策略)**: Agent 决定"下一步做什么"的决策逻辑
- **Observation Space(观察空间)**: Agent 能看到的全部信息
- **Action Space(动作空间)**: Agent 能做的全部事情的集合;开放式的动作空间(可生成任意自然语言和代码)是现代 Agent 的共同特征
- **Trajectory(轨迹)**: Agent 执行过程中积累的消息历史(user/assistant/tool),每次 LLM 调用都看到完整轨迹
- **Harness(马具/驾驭)**: 模型之外的全部基础设施 —— 上下文 + 工具 + 约束 + 验证 + 纠正
- **Tool Calling / Function Calling**: 模型通过结构化方式调用外部工具的能力;流程为声明工具 → 模型决定调用 → 结果追加到上下文 → 模型生成下一步
- **Ablation Study(消融实验)**: 系统性去除某个组件观察影响,本章用于证明上下文各组件不可替代

## Mental Models

- **把 Agent 当 RL 智能体理解**: 实现层的 LLM/上下文/工具正好对应 RL 的 Policy/Observation/Action。这把"提示词工程"问题转化为"接口设计"问题
- **接口优于聪明**: 许多看似需要"更聪明模型"的问题,其实只是观察/动作空间的接口问题 —— 把数据纳入上下文,把操作封装成工具,不可解任务就变可解
- **Demo vs 生产**: 最小公式是 Demo 视角(能跑),扩展公式是生产视角(可靠)。后者完全包含前者并加了一圈安全网

## Anti-patterns

- **脱缰野马(无 Harness)**: 模型能力惊人但缺上下文/工具/验证/纠正,会编造结果、选错工具、出错无法恢复。例如退款场景下编造 API 结果回复用户
- **盲目循环**: 缺工具执行结果(Verify 缺失)时,Agent 会陷入无限循环反复执行同一动作
- **决策不连贯**: 缺思考过程(reasoning)时,前后决策互相矛盾
- **重复操作**: 缺历史消息时,Agent 失忆,从头重做已完成步骤
- **过度通用**: 通用工具不一定优于专用工具。支付、删除数据、生产部署等高风险操作必须封装为参数明确、权限受限、全程可审计的专用工具

## Worked Example

**实验 1-1 上下文消融实验**(★☆☆)揭示了上下文五组件的不可替代性:

| 实验组 | 系统指令 | 工具定义 | 思考过程 | 历史记录 | 工具结果 | 结果 |
|---|---|---|---|---|---|---|
| 完整基线 | ✓ | ✓ | ✓ | ✓ | ✓ | 正常工作 |
| 无工具定义 | ✓ | ✗ | ✓ | ✓ | ✓ | ✗ 无法调用工具 |
| 无思考过程 | ✓ | ✓ | ✗ | ✓ | ✓ | △ 决策不连贯 |
| 无历史记录 | ✓ | ✓ | ✓ | ✗ | ✓ | △ 重复操作 |
| 无工具结果 | ✓ | ✓ | ✓ | ✓ | ✗ | ✗ 盲目循环 |

**核心洞察**: 上下文决定了 Agent 能看到什么,而 Agent 只能基于它看到的信息做决策。缺失任何一个组件,决策能力都会严重退化。

**多币种收入汇总的 ReAct 轨迹**(3 次迭代、4 次工具调用完成任务):
1. 第 1 轮:reasoning "需要把 EUR/GBP/JPY 转 USD" → 并行调用 3 个 `convert_currency`
2. 第 2 轮:reasoning "已获得汇率,调用代码解释器汇总" → 调 `code_interpreter`
3. 第 3 轮:reasoning "所有计算完成" → 生成 FINAL ANSWER

## Key Takeaways

1. **公式即地基**: `Agent = LLM + 上下文 + 工具` 是讨论一切 Agent 问题的起点;`Agent = Model + Harness` 是把 Demo 推向生产的起点
2. **接口优于模型**: 模型固定时,扩展观察空间和动作空间是提升表现最有效的工程手段
3. **上下文是天花板**: 实验 1-1 证明,上下文决定了 Agent 能看到什么,而它只能基于看到的做决策 —— 这是第 2 章被作者称为"全书最关键一章"的原因
4. **ReAct 的本质是轨迹累积**: 上下文 = 静态前缀 + 轨迹;每次迭代都看到全部历史,这带来全局认知也带来压缩需求(第 2.7 节)
5. **生产竞争力在 Harness**: 当各家模型能力接近时,竞争优势转移到模型之外的工程实践 —— Claude Code 的 Harness 中绝大部分代码是约束/验证/纠正
6. **工具设计要分层**: 通用基础能力用于组合与探索;专用工具用于约束高风险和强业务规则操作
7. **构建 Agent 三原则**: 保持简单(从最简方案开始)、保持透明(显示规划/日志/决策轨迹)、保持迭代(从工作流起步,确需时才升级为自主)
