# Chapter 9: 多模态与实时交互

## Core Idea
Agent 要跳出"对话框",就要从纯文本输入输出扩展到**同时处理文字、语音、图像、视频、动作**的多模态,并在严格的时间预算内响应。本章刻意划清边界:静态图像/文档理解(一次输入、一次理解)已融入前面章节,多模态生成(生图/生视频)只是普通工具调用——**真正让架构发生质变的是"实时性"**:输入持续流动、输出必须限时交付。语音对话、GUI 操作、机器人控制三个场景看似无关,却共同被两道坎卡住——**延迟敏感 + 多模态持续输入**,这两道坎把它们推向同一个架构方向:**从串行流水线走向端到端模型**。语音走得最完整,可作参考系,后两个场景都能对照语音这条"问题→方案→终局"的演进线来看各自走到哪、卡在哪。

## Frameworks Introduced

- **语音架构三范式**(OpenAI 2026 GPT-Live 发布时的三分法,对应 ChatGPT 语音三代演进):
  - **范式一·级联(Cascaded)**:VAD→ASR→LLM→TTS 串成流水线,一棒接一棒。模块清晰可独立调优,但延迟累积;仍依赖 VAD 划轮次
  - **范式二·端到端全模态(Omni / turn-based)**:单一模型直接"听音频、想回复、说出来",三段合一,延迟更低、副语言信息保留;**但仍假设轮流说话**,靠 VAD 或语义判断切轮次
  - **范式三·全双工(Full-Duplex / Interactive)**:模型边听边说,同时处理输入输出,每秒做多次"该说/该听/该停/该打断/该调工具"决策,**彻底取消"轮流"假设**。Moshi(2024 研究先声)、GPT-Live(2026 生产规模)
  - 贯穿三代的同一主线:**如何摆脱"轮流说话"假设、摆脱 VAD 对轮次的猜测**。级联和 Omni 都依赖 VAD,只有全双工消解了轮次本身
  - When to use: 选语音架构时的第一坐标系;三种范式非新旧替代,而是不同延迟/成本约束下的并存取舍

- **级联流水线全链路流式化**:保留 VAD-ASR-LLM-TTS 模块分工,但各阶段尽早产出增量——ASR 边听边转、LLM 流式输出并切分小段、TTS 增量合成。真正重叠的是"用户说话与 ASR 转录"以及"LLM 生成剩余与 TTS 合成/播放",**不是三段从头并行**。更激进的**抢跑生成(speculative generation)** 可隐藏部分计算但仍须决定何时安全开口。流式化无法消除 VAD 的静默等待本身

- **流式语音感知(替代 VAD + ASR)**:传统 VAD+ASR 有三大根本问题——延迟累积(必须等 500-800ms 静音)、信息丢失(只输出二值信号,丢情绪/语气/环境声)、准确率下降(切碎片段破坏上下文连续性,邮箱/人名错误率上升)。两条解决路线:
  - **基于 LLM 的流式听觉感知**(Ultravox、Qwen2-Audio、Qwen2.5-Omni):骨干 LLM 后训练,从连续音频流直接输出语义响应,把"识别"和"理解"合一,继承世界知识与上下文学习
  - **轻量路线:把轮次判断塞进识别器**(Deepgram Flux、AssemblyAI Universal-Streaming、LiveKit/Pipecat 语义轮次检测):小流式识别模型加 LoRA,综合语义+静音判断"意思是否完整"。关键洞察:模型摇摆的根源往往是**训练标签用了"上帝视角"**(标到了决策点之后才出现的音频),改成"只用当下可得信息"标注,虚假摇摆就消失——**数据比架构更关键**
  - 模型输出统一事件流:文字 token + 声学事件专用标记(`<speak_start/end>`、`<interrupt>`、`<emotion:happy>`、`<laugh>`、`<noise>`)

- **思考架构三方案**(调和"实时响应"与"深度思考"矛盾,**不是线性迭代而是并存取舍**):
  - **方案一·快慢简单并行**:快思考 500ms 应付("让我想想"),慢思考 8-10s 深度作答。两大问题——简单问题过度思考(已答完又被重复)、快慢不一致(几秒内听到自相矛盾回答,信任崩塌)。根本原因:把对话拆成两个独立思考过程,缺协调机制
  - **方案二·快思考交互、慢思考提醒("军师"路线)**:慢思考看得到快思考输出,通过 Agent 状态栏幕后建议而非直接对话。GPT-Live 委派、Pine AI、Grok Voice "Think Fast" 均此方案。局限:沟通间接模糊、看不到中间思考结果、**无法实现"边想边说"**
  - **方案三·端到端思考与表达统一(Step-Audio R1)**:把思考内化进单一模型。两个互补机制——**MGRD(模态锚定思考蒸馏)** 解决"想得对不对"(治"文本代理思考":模型其实在分析转录文本而非声学特征,思考链越长性能越差);**MPS 双脑架构(构思脑 + 表达脑)** 解决"说得及不及时"(模拟人脑思考区与语言区分工,流水线并行实现低延迟边想边说)
  - 分野提示:方案一二本质是"两个独立模型并发"的快慢分工,**不依赖端到端**,可套在级联之上;只有方案三把思考真正内化进端到端模型
  - 产业分野:追求"可随时换最新大脑"的前沿产品押方案二(前沿推理模型几月一迭代,塞进同一模型等于追移动靶),追求极致自然度且愿付训练成本者押方案三

- **快慢接口 / Latent Bridge(潜空间桥)**:方案二里慢→快"递话"用文本通道(状态栏传一句建议),文本好懂好调试,却是慢思考中间状态的一根细吸管。在实时游戏这类最苛刻场景,**冻结快慢两模型只训练它们之间一个几千万参数的小"桥"**,把慢模型隐层结论投影成几个"潜 token"像视觉 token 那样拼进快模型输入——绕开"想法→文字→再理解"往返。多 Atari 游戏比文本通道高 +26%~+82%,每步仅多约 5ms。**诚实边界**:快慢协作有没有用取决于瓶颈在"想不想得到"还是"来不来得及反应",慢思考本就比快反应强时桥才帮得上忙(相关性 r≈0.9)

- **Computer Use 感知-思考-行动循环**:截图 → 多模态模型(截图+任务指令)输出思考与动作 → 执行层(xdotool/Playwright)执行 → 等待界面稳定 → 再截图。三关键维度:动作空间、视觉定位、模型架构

- **视觉定位三路线**:
  - **Set-of-Mark(纯视觉标注)**:分割模型(SAM/SEEM)在截图切候选区域叠编号,模型报编号→换算坐标;不需 DOM,适用原生桌面/游戏
  - **结构化元素索引**(browser-use):CDP 获取 DOM/A11y Tree,枚举可交互元素编号——SoM 思想在 Web 的结构化实现,定位最精确稳定。适用边界:结构化界面;Canvas/WebGL/游戏需回退纯视觉
  - **纯坐标预测**(SeeClick、Claude computer use):海量 GUI 截图+元素位置配对训练,直接输出坐标。**坐标理解高度依赖训练分辨率**,须按宽高比选目标分辨率(XGA/WXGA/FWXGA)并实现双向坐标缩放,避免非等比拉伸带偏坐标

- **Agent-电脑观察接口(AOI)**:重新设计"观察接口"而非"动作接口"——把观察(连续/自适应/多模态)从动作(离散)解耦,做成插在环境与现成 Computer Use 模型之间的无需重训的感知中间件。三部件:帧间关键帧捕获(廉价像素门+小模型判变化)、音量门控语音转写(让 Agent 长耳朵)、**把帧叙述成持久文字**(最关键——文字才是 LLM 最擅长处理的模态,即使原图清出上下文文字仍留记忆)。反直觉发现:真正起作用的不是"选哪几帧"而是"把帧叙述成能长期留存的文字";8 个模型(7B~前沿)无需重训 +17~+48 个百分点,但塞太多图 token 在某些更新模型上反拖累表现——**部件要按模型逐个挑选**

- **机器人双层架构**:长程规划(0.1-1Hz,通用 VLM/Gemini Robotics-ER 1.5,负责"做什么")+ VLA 控制(1-10Hz,RT-2/OpenVLA/π₀,负责"怎么做")。与语音快慢思考结构同构——但切的是"谋划全局 vs 实时执行",**不同于** MPS"构思脑/表达脑"切的是"想 vs 说"。实时性没消失而是下推到 VLA 层靠动作分块摊薄

- **动作分块(Action Chunking)**:LLM 推理只有 1-10Hz,传统控制要 50-1000Hz(差两个数量级)。模型一次推理生成未来一小段动作序列(π₀:50Hz 下 25-50 个动作),控制线程高频回放,后台异步生成下一批。**只要推理时间 < 这批动作执行时间,运动就连续**。权衡:**拿反应性换平滑性**——块越长越连贯,但模型这段时间"看不到"新画面,对突发变化越迟钝

- **VLA 动作表示两路线**:离散动作 token(RT-2/OpenVLA,像生成文本逐 token 自回归,借预训练泛化) vs **连续轨迹生成(π₀,flow matching 从噪声去噪生成平滑轨迹,天然配动作分块,灵巧操作更优)**

- **Sim2Real + Domain Randomization**:仿真无法完全还原真实物理/视觉/硬件,训练时把这些参数大范围随机打乱,逼策略学出对各种变化都稳的通用表征(真实世界只是"其中一个样本")。落地两工程环节:**随机化范围标定**(从真实数据实测分布采样,掉点再逐步扩大)和**视觉对齐**(校准摄像头位姿 + greenscreen 背景替换)。成功案例:Dactyl(解魔方)、ANYmal(野外地形)

## Key Concepts

- **全双工 / Full-Duplex**:模型同时持续地听和说,取消"轮流说话"假设;微轮次(micro-turn,~200ms/段)让多路模态流交织推进
- **VAD(Voice Activity Detection)**:语音活动检测,判断用户何时说完;传统靠 500-800ms 连续静音阈值,是级联和 Omni 流派共同的轮次判断瓶颈
- **Omni(全模态 / turn-based)**:单一模型处理音频听想说,但仍轮流说话;OpenAI 称 turn-based,工业界称 Omni,同一物
- **自级联(self-cascade)**:同一模型先把音频转结构化文本再据此推理;与一次性端到端相比,何者更准**取决于任务**——语义内容主导时自级联相当或更优,依赖非语言线索时端到端占优。决定性能的关键不在中间表示本身,而在**它承载的信息**
- **文本代理思考(Textual Surrogate Reasoning)**:音频模型 CoT 多由文本模型生成,模型"思考"时实际基于转录文本而非声学特征;思考链越长性能越差的根因
- **Latent Bridge(潜空间桥)**:冻结快慢两模型,只训它们之间的小桥,把慢模型隐层结论投影成潜 token 拼进快模型
- **VLA(Vision-Language-Action)**:VLM + 动作输出,"看懂想清楚"基础上还要"动手"
- **OSWorld / OSWorld-Human**:Computer Use 基准;Human 效率研究揭示 Agent 步骤明显多于人、步骤耗时随任务推进持续增长——准确率接近人类≠实用,**效率才是真瓶颈**
- **Whisper coding**:以口述指挥编程/研究 Agent 的高阶用法;作者团队十余篇论文以此方式完成

## Mental Models

- **三个场景同一道考题**:语音(听觉模态延迟)、Computer Use(视觉模态延迟)、机器人(物理模态延迟,且动作不可逆)——都面对"实时感知 + 低延迟决策 + 持续交互",都从串行流水线走向端到端
- **替代 VAD 叙事链**:VAD 靠静音阈值猜轮次切换 → 流式感知把切换升级到语义层(局部修补)→ 全双工彻底消解"切换"本身(打断不再是事件,barge-in 处理链大部分被省去)
- **快慢分工 = 把移动靶拆成两个固定靶**:前沿推理模型几月一迭代,实时交互需专门数据和训练目标;塞同一模型等于追移动靶还稀释推理力。只把最强推理原封不动放后台、只训轻量交互模型在前台,就能始终用上当下最强大脑
- **"可换的大脑" vs "更紧的边想边说"**:方案二(解耦)与方案三(统一)不是谁取代谁,而是取舍——前者追求随时换最新大脑,后者追求极致自然度
- **把"慢"藏起来**:当某环节天生慢,就让另一个快环节填满用户等待。语音-操作解耦让语音回应比单模型边操作边说话快约 15 倍(0.58s vs 8.64s),成功率不降;那份"纯文本契约"本质就是 Agent 状态栏
- **端到端 ≠ 更准确**:端到端的优势在延迟而非准确率;自级联在文字足以承载信息的任务上相当乃至更优
- **数据比架构更关键**:轮次判断的虚假摇摆根源在"上帝视角"标签而非模型结构;感知方案没有银弹,要顺着模型脾气配

## Anti-patterns

- **把"端到端"直接等同"更准确"**:两臂总分可能相同但失败位置相反(语义题自级联更准、副语言题端到端更准)——盲目选端到端会在不该用的任务上掉点
- **方案一简单快慢并行无协调**:几秒内听到自相矛盾回答,信任瞬间崩塌。根因是拆成两个独立思考过程
- **方案二把慢思考当直接说话者**:慢思考直接对用户说话会打断节奏;应退到幕后当军师通过状态栏递话
- **只追求"选哪几帧"而忽视"把帧叙述成持久文字"**:AOI 的反直觉发现——真正起作用的是文字留存而非帧选择
- **对所有模型一股脑全开感知中间件**:某些更新模型上塞太多图 token 反挤占推理拖累表现;部件要按模型逐个挑选
- **坐标缩放不看宽高比**:硬把 16:9 拉进 4:3 会横向压扁画面,模型预测坐标系统性偏移;须按宽高比选最匹配训练分辨率
- **把 4:3 的"规划/控制"解耦混同于"想/说"解耦**:机器人双层架构切的是"谋划全局 vs 实时执行",MPS 切的是"想 vs 说",两种"双 X 架构"维度不同
- **以为遥操作反证意味着硬件全面过关**:它只证明"现有低成本硬件+人类智能足以完成视觉反馈为主的家庭操作";触觉传感缺失、灵巧手可靠性与成本仍是硬件短板

## Code Examples

**流式语音感知替代 VAD+ASR 的事件流输出**(范式一·轻量路线,模型输出统一事件流):

```
Input audio: "Um, actually I think... no wait, let me reconsider."
Model output stream:
  <speak_start> Um, <emotion:hesitant> actually I think...
  <silence:500ms> no wait, <emotion:confident> let me reconsider <speak_end>
```
- What it demonstrates: 模型输出不仅是文字转录,还包括语音事件标记(说话起止/情绪/沉默);Agent 据此实现更自然交互(检测犹豫主动提供选项)

**Computer Use 感知-思考-行动循环**(伪代码):

```python
def computer_use_loop(task, max_steps=25):
    for step in range(max_steps):
        screenshot = capture_screen()
        # 缩放到训练分辨率(按宽高比选),避免坐标偏移
        scaled = resize_to_training_resolution(screenshot)
        # 模型接收截图+任务,输出思考与一个动作
        output = model.infer(scaled, task)
        action = output.action          # e.g. click(683,384) / type("weather")
        # 坐标反向映射回真实分辨率后执行
        real_action = rescale_coords(action, screenshot.size, scaled.size)
        execute(real_action)            # xdotool / Playwright
        wait_for_ui_stable()
        if output.done:
            return output.answer
```
- What it demonstrates: 每步只一个动作,坐标双向缩放是硬约束;每步 2-5s(人类速度 1/3~1/5),多步表单需 10-20 轮

**快慢解耦的纯文本契约**(语音+操作并发,把"慢"藏起来):

```python
# 慢 Agent(前沿 VLM)每次操作附带滚动更新的状态摘要
slow_agent_state = "正在填表单,还需要你的出生日期"  # ← 纯文本契约
# 快 Agent(小语音模型)据此实时答用户,并转达用户新信息
fast_agent_reply = voice_agent.respond(user_input, slow_agent_state)
# 状态摘要确认完成前,快 Agent 绝不许说"办好了"
if not slow_agent_state.contains("完成"):
    assert "办好了" not in fast_agent_reply
```
- What it demonstrates: 快慢间只靠极简文本契约(本质是 Agent 状态栏),语音回应快 15 倍且成功率不降;抽掉文本通道成功率塌到 0

## Reference Tables

**语音三范式对比**(沿"如何摆脱 VAD 轮次假设"轴):

| 维度 | 级联 Cascaded | 端到端 Omni(turn-based) | 全双工 Full-Duplex |
|---|---|---|---|
| 架构 | VAD→ASR→LLM→TTS 串行 | 单模型听想说,三段合一 | 单模型边听边说,持续并发 |
| 依赖 VAD | 是(切轮次) | 是(切轮次,可语义增强) | **否(取消轮次)** |
| 典型延迟 | 0.95-2.3s(空载)+ 排队放大 | 更低(Qwen3-Omni 首包 234ms) | ~200ms(Moshi)/ 0.40s(TML) |
| 打断处理 | 难 | 检测到用户开口停生成 | 天然行为,无需专门逻辑 |
| 副语言信息 | 交接时丢失 | 隐空间内保留 | 保留 |
| 可解释性 | 好(模块清晰) | 差 | 差 |
| 代表 | 早期 ChatGPT Voice | ChatGPT 高级语音/Qwen3-Omni/Step-Audio 2 | Moshi/GPT-Live/TML-Interaction |

**思考架构三方案对比**:

| 维度 | 方案一 简单并行 | 方案二 军师提醒 | 方案三 内化统一(Step-Audio R1) |
|---|---|---|---|
| 慢思考角色 | 直接对用户说 | 状态栏幕后建议 | 内化进模型 |
| 依赖端到端 | 否 | 否 | **是** |
| 快慢协调 | 无(独立并行) | 间接模糊(递纸条) | 同一模型内部 |
| 边想边说 | 不能 | 不能 | **能(MPS 双脑)** |
| 主要风险 | 自相矛盾/过度思考 | 误解状态栏/看不到中间结果 | 移动靶子需反复重训 |
| 产业取向 | (已淘汰) | GPT-Live/Pine AI/Grok Voice | 追求极致自然度 |

**Computer Use 视觉定位三路线**:

| 路线 | 机制 | 适用 | 取舍 |
|---|---|---|---|
| Set-of-Mark(纯视觉) | 分割模型切区域叠编号 | 原生桌面/游戏/Canvas | 不需 DOM,通用模型友好;分割可能漏检 |
| 结构化元素索引 | DOM/A11y Tree 枚举可交互元素 | 标准 Web | 最精确稳定;不省 token |
| 纯坐标预测 | 训练视觉模型直接出坐标 | 做过 GUI 定位训练的模型 | 省标注;依赖训练分辨率须双向缩放 |

## Worked Example

**语音 Agent 串行延迟拆解(范式一·级联,空载理想)**:用户说话 2-3s → VAD 等 500-800ms 静音确认说完 → ASR 转录 50-200ms → LLM 首 token(TTFT)100-500ms + 生成短句 100-300ms → TTS 合成 200-500ms,**合计约 0.95-2.3s**。这还只是空载;投入生产后排队延迟让情况雪上加霜——排队论 `总延迟 ≈ 空载延迟 × 1/(1-利用率)`,利用率 50% 变 2 倍,80% 变 5 倍,逼近 1 时趋向无穷。这也是为何生产环境利用率通常控制在 0.5-0.8、实际延迟是空载的 2-5 倍。开启 reasoning 时 LLM 等待可能延长到 5-10s。结论:模块化让组件可独立优化,但延迟累积是结构性代价,推动架构走向端到端。

**Computer Use 完成一个 GUI 任务(实验 9-7,开放模型路径)**:任务"打开 Google 查旧金山天气"。系统启动后截图显示 Google 搜索页,交互元素被编号(SoM);模型选搜索框→输入"San Francisco weather today"→提交;第 4 步遇 CAPTCHA,**模型没有宣称成功**而是转到 weather.com;最终第 16 步从 San Francisco Today 页读取 64°F、Sunny、体感 62°F、高 74°F、低 55°F。16/16 个 API 响应均报告 qwen3-vl-32b-instruct,15 张有效步骤截图与只读动作轨迹通过独立确定性验收。要点:(1) 准确率接近人类但**操作步骤明显多于人**、每步 2-5s;(2) 模型诚实处理 CAPTCHA 而非虚报成功;(3) 开放模型 API 路径可运行 ≠ Anthropic 原生 computer 工具臂已复现。

## Key Takeaways

1. **三场景同一道考题**:语音、Computer Use、机器人都被"延迟敏感 + 多模态持续输入"推向端到端。语音走得最完整,作参考系
2. **替代 VAD 是贯穿语音三范式的主线**:VAD 静音阈值 → 流式感知语义判断(局部修补)→ 全双工消解轮次本身(终点)
3. **端到端 ≠ 更准确**:优势在延迟;自级联在文字足以承载信息的任务上相当或更优。决定性能的是中间表示承载的信息,不是表示本身
4. **思考架构三方案是并存取舍不是迭代**:方案一二不依赖端到端,可套级联;产业主流押方案二解耦(可换最新大脑),方案三适合极致自然度
5. **快慢接口不止文字**:Latent Bridge 用潜 token 绕开"想法→文字→再理解"往返;但快慢协作有没有用取决于瓶颈在"想得到"还是"来得及反应"
6. **把"慢"藏起来**:当环节天生慢,让快环节填满等待——纯文本契约(本质是 Agent 状态栏)让语音-操作解耦快 15 倍且成功率不降
7. **数据比架构更关键**:轮次判断摇摆源于"上帝视角"标签;文本代理思考源于 CoT 数据由文本模型生成
8. **Computer Use 准确率接近人类,但效率是真瓶颈**:步骤多于人、步骤耗时随任务推进增长;循环本身提速尚无系统解法,但快慢解耦已可用
9. **机器人硬件非瓶颈(视觉反馈为主的任务内),算法才是**:双层架构把实时性下推到 VLA 层靠动作分块摊薄;主要矛盾已转到训练与泛化;触觉/灵巧手仍是硬件短板
10. **感知方案没有银弹**:SoM/DOM/坐标预测三路线按界面类型选;AOI 部件按模型逐个挑选——顺着模型脾气来配
